P5.3-E9：训练预算与数据规模实验预注册 V0.1（含第三次测试集前向的预先声明）

1. 文档状态与目的

本文件在 E9 任何训练开始前冻结两个子研究的设计、校验门槛与判定规则。执行期间不得根据已观察结果改变预算、样本量或 seed；任何必要更改必须先停止、说明原因并留痕。

背景：报告 V0.4.1 §13.2 局限 #1（仅用 20,000 训练样本）与 §13.1（"权衡在 20k/30 epoch 预算内成立，预算变化后可能不同"）。E9 目的：在**不改变既有选型结论**的前提下，量化 (a) 延长训练预算、(b) 使用完整 60,000 训练样本对最终配置的影响。E9-B 全部 validation-only；E9-A 涉及对官方测试集的**第三次前向传播**，在本文件 §5 预先声明。

前置条件：同 e7.md §1；60k 驱动脚本为新增文件（只 import 冻结 `src` 模块，不修改任何冻结文件），须先通过 §5 的逐位复现校验门槛方可运行 60k。

2. E9-B：延长训练预算（validation-only，6 次运行）

配置 = E6 最终配置（[256]/relu(auto)/momentum_sgd lr0.05/λ=0.0001/none），仅改两处：epochs 30→**100**；早停开关 ∈ {false, true(patience=5, min_delta=0.0001)}。seed = 404/505/606（与 E6 相同）。输出 `outputs/p5.3/E9_budget_data/e9b_budget100/`。

确定性校验（执行时强制）：与 E6 同 seed 同配置仅 epochs 不同 → no_es 组每个 run 的 history.csv **前 30 个 epoch 的数值列必须与 E6 对应 run 逐位一致**（逐 epoch shuffle 的 RNG 消耗与总 epoch 数无关）。不一致即停止调查。

判定（描述性，3 seed）：对比 30ep（E6 冻结值，只读引用）与 100ep 的 best_validation_loss / accuracy 均值±std、best_epoch 位置；es 组如实报告实际停止 epoch 与节省比例。结论措辞限定"在 100 epoch 预算内"；不因结果追加预算档位。

3. E9-A：完整 60,000 训练样本（3 次运行 + 一次单独的测试集前向）

- 配置 = E6 最终配置，仅改：train_size 20000→**60000**，val_size 5000→**0**（无验证集，故无 best-epoch 选择），epochs=30 固定预算，取**最终 epoch** 参数为交付参数。seed = 404/505/606。输出 `outputs/p5.3/E9_budget_data/e9a_full60k/`。
- 驱动：新脚本 `train_full60k.py`，复刻 `training.train_model` 循环语义（同一 MLP/损失/优化器/L2 辅助/小批量迭代函数，同一 RNG 派生方式，eval batch 1000），逐 epoch 记录 train 数据损失、train objective（含 L2）与 train accuracy；产物为 config.json（注明 driver 与协议差异）、history.csv、final_model.npz、summary.json。
- **校验门槛（先于 60k）**：驱动在 20k/5k/30ep/no-es 模式下运行 seed=404，与冻结 `e6_final_seed404` 对账：history.csv 除 elapsed_seconds 外逐位一致、best epoch/验证指标逐位一致、checkpoint 全部参数数组逐位一致。**通过后才允许跑 60k**；不通过则停止并修复驱动（属基础设施问题，按 e7.md §5 重跑规则留痕）。
- 协议差异披露（写入报告）：无验证集 → 无 early stopping、无 best-epoch 选择，与 E1–E6 的"验证集选最佳 epoch"不可直接比较；两研究只比较最终 epoch 与训练动态。

4. E9 判定总规则

- E9 结果**不得**用于更改 E6 选型、最终模型或任何已冻结结论；报告 §13.3 的最终模型仍为 E6 三模型。60k 模型为补充研究对象，即使其测试指标更高，也**不替换交付模型**（预注册纪律：交付模型由预注册流程产生，非事后择优）。
- 全部结论限定"本预算/本切分协议下"；3 seed 描述性统计（E9 无预注册推断检验；不使用"显著"一词）。

5. 测试集纪律与第三次前向（预先声明）

- E9-B 与 E9-A 训练阶段一律 `evaluate_test=false`（60k 驱动不包含任何测试集调用）。
- **第三次测试集前向**：E9-A 三个 60k 最终模型的评估需要一次独立前向传播。**该评估在本文件冻结时（2026-11-08，任何 60k 训练开始之前）预先声明**，目的：量化完整训练集的泛化变化，量化局限 #1。执行方式与既有补充评估相同：单独脚本、只读加载 final_model.npz（经 `load_checkpoint` 安全重建）、官方 10,000 测试样本各前向**一次**，计算 loss/accuracy/混淆矩阵/逐类 P-R-F1，落盘 `derived_data/e9a_full60k_test_eval.json`；不改任何冻结产物，不用于任何选型。
- 披露：报告 §13.2.8 如实记录两次补充前向（2026-10-30 ROC/AUC 与样例展示；2026-11-08 60k 数据规模研究），各自目的与"逐位一致/未用于选型"的核验事实分列。测试集前向总次数为**三次**。

6. 产物与验收纪律

E9-B 每 run 四件产物齐全、测试键 null；E9-A summary 的测试两键在 §5 评估执行前为 null，执行后由评估脚本另立文件记录，训练产物仍保持 null 不回填。aggregate --strict 仅适用于 E9-B（6 条成功记录）。冻结产物 237 项哈希在 E9 前后零变化。
